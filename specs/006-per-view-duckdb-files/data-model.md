# Data Model: Per-View DuckDB Files

**Date**: 2026-07-25

## Entities

### Per-View DuckDB File

Represents a single `.duckdb` file generated by the storage stage.

| Field | Type | Description |
|-------|------|-------------|
| filename | string | Derived from view name: `{view_name}.duckdb` |
| view_name | string | SQL view name (e.g., `v_monthly_revenue`) |
| base_table | table | `sales` table with 34 columns (identical across all files) |
| view | view | Single SQL view over `sales` |

**Files generated** (one per view):

| Filename | View Purpose |
|----------|-------------|
| `v_monthly_revenue.duckdb` | Revenue trends by year/month |
| `v_store_performance.duckdb` | Sales rep performance by region |
| `v_category_sales.duckdb` | Revenue by product category/subcategory |
| `v_top_products.duckdb` | Product ranking by revenue |
| `v_sales_summary.duckdb` | Overall KPI summary (single row) |

### Sales Table (duplicated per file)

The `sales` table is identical across all 5 files. Schema unchanged from current implementation (34 columns). See `specs/005-duckdb-storage/data-model.md` for full column definitions.

### Views (one per file)

Each view is defined in `src/sql/create_views.sql`. The SQL is unchanged — only the execution strategy changes (single file → per-file).

## Relationships

```
Per-View DuckDB File (1)
├── sales table (1) — base data, 34 columns
└── view (1) — groups/aggregates sales data
```

## Validation Rules

- Each `.duckdb` file MUST contain exactly 1 table (`sales`) and exactly 1 view
- The `sales` table MUST have identical row count and `SUM(net_revenue)` across all files
- View query results MUST match the expected output from the SQL definition

## State Transitions

```
[DataFrame] → store_analytics() → [5 .duckdb files]
                                       │
                                       ├── v_monthly_revenue.duckdb
                                       ├── v_store_performance.duckdb
                                       ├── v_category_sales.duckdb
                                       ├── v_top_products.duckdb
                                       └── v_sales_summary.duckdb
```

Idempotent: re-running overwrites all files completely.
